# Datasets

Everything in this course comes from one study:

> **He J, Luo S, Xu W, Chen Y, Liu G, Tang J, Yang Y, Zhao B, Ma L, Sheng H, Mao E.**
> *Serum proteomic profiling of sepsis patients reveals a protein-based diagnostic model,
> with metabolomic insights into carbapenem-resistant Klebsiella pneumoniae infection.*
> Front Immunol. 2026;17:1818068. [doi:10.3389/fimmu.2026.1818068](https://doi.org/10.3389/fimmu.2026.1818068)
> · [PDF in this repository](../publication/fimmu-17-1818068.pdf)

Open access, CC BY. The paper and its nine supplementary tables are under
[`publication/`](../publication/).

## 1. The cohort

Serum collected at the time of sepsis diagnosis from patients in the emergency departments
and ICUs of four Shanghai hospitals (Ruijin, Shanghai Tenth People's, Gongli, Fifth
People's), April–December 2025. Ethics: Ruijin Hospital, Shanghai Jiao Tong University
School of Medicine (2025–155).

**Discovery cohort — the one we use — 45 patients, 15 per group:**

| Group | Sample IDs | Description |
|---|---|---|
| `Con` | `Con1` … `Con15` | Sepsis; all clinically indicated cultures negative |
| `CSKP` | `KP1` … `KP15` | Sepsis with confirmed carbapenem-**susceptible** *K. pneumoniae* |
| `CRKP` | `CRKP1` … `CRKP15` | Sepsis with confirmed carbapenem-**resistant** *K. pneumoniae* |

A separate **validation cohort** of 45 patients was profiled by targeted PRM only. Its
clinical data are in supplementary table 1 (sheet *validation cohort*); the PRM
measurements themselves were not deposited, so the course does not use them — but they are
the reason to take the paper's key proteins more seriously than a single-cohort result.

Inclusion required age ≥ 18 and, for the infected groups, ICU stay ≥ 48 h and a confirmed
CRKP/CSKP infection. Excluded: pre-existing CRKP/CSKP infection at admission, colonisation
without active infection, substantial missing clinical data.

## 2. Proteomics — PXD075261

Deposited with the ProteomeXchange Consortium via the **iProX** partner repository under
**PXD075261**.

| | |
|---|---|
| Matrix | serum, 20 µL, enriched with superparamagnetic iron-oxide nanoparticle beads |
| Sample preparation | TCEP reduction, CAA alkylation, 1 % SDC, overnight trypsin digestion, SDB-RPS desalting |
| LC | UltiMate 3000 RSLCnano; C18 trap 75 µm × 2 cm (3 µm); analytical column 75 µm × 15 cm (1.7 µm, IonOpticks); 300 nL/min; 0.1 % formic acid / acetonitrile |
| MS | **timsTOF Pro** (Bruker), CaptiveSpray, capillary 1500 V |
| Acquisition | **diaPASEF**; MS1 and MS2 100–1700 *m/z*; ion mobility 0.6–1.6 V·s/cm²; accumulation and ramp 50 ms; collision energy ramped 59 → 20 eV; windows defined in timsControl |
| Search | **DIA-NN 1.9.2**, library-free, HUMAN UniProt (release 20250113) |
| Search parameters | Trypsin/P, ≤ 2 missed cleavages; fixed Carbamidomethyl (C); variable Oxidation (M) and Acetyl (protein N-term); MS1 and MS2 tolerance 15 ppm; match-between-runs on; heuristic protein inference; **1 % FDR** |
| Quantification | **MaxLFQ** |
| Runs | 48 = 45 patients + 3 pooled QC injections (`mix1`–`mix3`) |

### Raw files

`.d` directories, distributed as `.d.zip` (about **2.4 GB each**, ~115 GB in total). Three
representative samples — one per group — are kept locally under
[`proteomics/data/raw/`](../proteomics/data/raw/):

```
25062408_HJ_Con10_GE3_1_50924.d.zip
25062408_HJ_KP15_GF11_1_50966.d.zip
25062408_HJ_CRKP12_GG11_1_50992.d.zip
```

Each archive contains `analysis.tdf` (an SQLite database of frame metadata, ~140 MB) and
`analysis.tdf_bin` (the compressed spectra, ~2.5 GB), plus the acquisition method.

> These files are **not committed** to git — see [`.gitignore`](../.gitignore). Download them
> from PXD075261 if you want them. `quantmsdiann` accepts `.d.zip` directly, so there is no
> need to unpack.

### Processed output

[`proteomics/data/raw/report.pg_matrix.tsv`](../proteomics/data/raw/report.pg_matrix.tsv) —
the authors' DIA-NN protein-group matrix: 1 458 protein groups × 48 runs, plus
`Protein.Group`, `Protein.Names`, `Genes`, `First.Protein.Description`. Column headers are
the original Windows paths of the `.d` folders.

### Metadata for the pipeline

Two **SDRF** files, both generated by [`bin/build_sdrf.py`](../bin/build_sdrf.py) and
consumed directly by `quantmsdiann`. See [`quantmsdiann.md`](quantmsdiann.md) for how to run
them.

| File | Runs |
|---|---|
| [`proteomics/data/PXD075261.sdrf.tsv`](../proteomics/data/PXD075261.sdrf.tsv) | all 45 patients |
| [`proteomics/data/PXD075261_subset.sdrf.tsv`](../proteomics/data/PXD075261_subset.sdrf.tsv) | `Con10`, `KP15`, `CRKP12` — one per group, matching the raw files kept locally |

Both have been validated by running `parse_sdrf convert-diann` (sdrf-pipelines 0.1.5, the
version the pipeline uses) and checking that the resulting `diann_design.tsv` has the
expected number of rows and file names.

Two notes on its content:

- `comment[instrument]` is written as `NT=timsTOF Pro` without an ontology accession, because
  the exact PSI-MS accession for this model was not verified when the file was built. Add
  `AC=MS:...` if you confirm it — `timsTOF Pro 2` is `MS:1003230` and `timsTOF SCP` is
  `MS:1003005`, so do not guess.
- The three pooled QC injections are **excluded** from the SDRF: including them would put
  them into the differential design. Add them back with a distinct
  `factor value[disease]` if you want them in the QC report.

## 3. Metabolomics — MTBLS14016

Deposited in **MetaboLights** under
[**MTBLS14016**](https://www.ebi.ac.uk/metabolights/MTBLS14016).

| | |
|---|---|
| Extraction | 50 µL serum + 300 µL acetonitrile:methanol (1:4) with internal standards; vortex, centrifuge 12 000 rpm 4 °C, cold precipitation, re-centrifuge |
| LC | SCIEX ExionLC AD; Waters ACQUITY UPLC HSS T3 C18, 1.8 µm, 2.1 × 100 mm; 40 °C; 0.4 mL/min; 2 µL injection; 10-minute gradient (95:5 → 1:99 → 95:5, water/acetonitrile, both with 0.1 % formic acid) |
| MS | **QTRAP 6500** (SCIEX), ESI, source 500 °C, ±5500/−4500 V, curtain gas 25 psi |
| Acquisition | **MRM**, widely targeted, transitions monitored per elution window, positive and negative mode |
| Features | 1 073 named metabolites |
| Injections | 45 patients + 6 pooled QC (`QC01`–`QC06`), single batch |

### Raw files

Per-sample, per-polarity `.mzML` (≈ 4 MB each), converted from SCIEX `.wiff` with
ProteoWizard. **None of them are committed to git.** The Day 1 metabolomics notebook fetches
the file it needs directly from the MetaboLights FTP server:

```
https://ftp.ebi.ac.uk/pub/databases/metabolights/studies/public/MTBLS14016/FILES/DERIVED_FILES/<sample>.mzML
```

and [`metabolomics/data/raw/download.sh`](../metabolomics/data/raw/download.sh) fetches all
five samples used by the notebook and its exercises, in both polarities:

```
Con10_P.mzML   Con10_N.mzML
KP11_P.mzML    KP11_N.mzML
KP12_P.mzML    KP12_N.mzML
KP15_P.mzML    KP15_N.mzML
CRKP12_P.mzML  CRKP12_N.mzML
```

Naming is `<sample>_P` / `<sample>_N` for positive and negative mode. Each file contains
**chromatograms and no spectra**: a TIC, a BPC, and roughly 1 550 (positive) or 1 290
(negative) SRM traces. Two consequences:

- **Untargeted pipelines cannot process these files.** There is nothing to pick peaks from.
  This is why the Day 1 metabolomics session runs `nf-core/metaboigniter` on a separate
  untargeted dataset and uses these files only to show where a peak area comes from.
- The mzML `run` identifier still refers to the multi-sample `.wiff` batch file the sample
  was extracted from (`..._AutoQC5.wiff`, `sample=14`), not to the patient. Trust the file
  name and the MAF column headers, not the internal identifier.

### ISA-Tab metadata

Under [`metabolomics/data/raw/metadata/`](../metabolomics/data/raw/metadata/), as downloaded
from MetaboLights:

| File | Contents |
|---|---|
| `i_Investigation.txt` | study description, protocols, publication |
| `s_MTBLS14016.txt` | sample table: organism, organism part, factor values |
| `a_MTBLS14016_LC-MS_{positive,negative}__metabolite_profiling.txt` | assay tables: instrument, column, polarity, derived file per sample |
| `m_MTBLS14016_LC-MS_{positive,negative}__metabolite_profiling_v2_maf.tsv` | **metabolite assignment file** — the quantification matrix |

⚠️ **Two defects in this submission**, both worth knowing about because they are typical:

1. The two MAF files are **byte-identical**. They are one combined table of 1 073
   metabolites in which the adduct (`[M+H]+`, `[M-H]-`, …) encodes the mode, not two
   mode-specific tables.
2. In the assay tables the `Sample Name` and `Extract Name`/`MS Assay Name` columns are
   **misaligned** — one was sorted independently of the other, so row *i* pairs the wrong
   sample with the wrong file. Do not use the assay tables to map samples to files. The MAF
   column headers and the derived-file names are consistent and are what we use.

Injection order is **not reported anywhere**, so LOESS/QC-based drift correction cannot be
applied. The paper states that all samples were run in a single batch.

**What the repository does not contain:** the raw mass-spectrometry files. The proteomics
`.d.zip` archives are ~2.4 GB each and the metabolomics `.mzML` about 4 MB each; both are
excluded by [`.gitignore`](../.gitignore) and fetched from the public repositories on demand.
Everything the notebooks need to run is either a curated table above or a download away.

The `published_*` tables exist so that the class can compare its own results with the
published ones. That comparison is one of the most instructive things in the course: the
effect sizes agree closely while the *lists* differ, because a differential list is a
property of the data **plus the analyst's choices**.

### Sample-identifier harmonisation

The two repositories do not name the patients identically, and the harmonisation is done
once, in `bin/build_curated_data.py`:

| Where | Carbapenem-resistant group | Pooled QC |
|---|---|---|
| DIA-NN column headers | `CPKP1`–`CPKP15` | `mix1`–`mix3` |
| Deposited proteomics file names | `CRKP1`–`CRKP15` | — |
| MetaboLights MAF headers | `CRKP1`–`CRKP15` | `QC01`–`QC06` |
| Clinical table, paper, this course | `CRKP1`–`CRKP15` | `QC_pool1`–`3` / `QC01`–`06` |

The susceptible group is `KP*` in both repositories while the paper calls it **CSKP**; we
keep the repository identifiers and carry the group label in a separate `group` column.

Nothing warns you about any of this. Join on the wrong string and 15 patients vanish from
the integration silently, with no error and no change in matrix shape — which is why the
multi-omics notebooks assert the intersection size before doing anything else.

## 5. ⚠️ Acquisition order is confounded with group

Recovered from the proteomics file names, which encode the plate well and a sequential
instrument run identifier:

| Block | Run IDs | n |
|---|---|---|
| `Con` | 50906 – 50934 | 15 |
| *pooled QC* | 50936 | 1 |
| `KP` (CSKP) | 50938 – 50966 | 15 |
| *pooled QC* | 50968 | 1 |
| `CPKP` (CRKP) | 50970 – 50998 | 15 |
| *pooled QC* | 51000 | 1 |

All controls were injected first, then all CSKP, then all CRKP, with a pooled QC injection
at each boundary. **Run order is therefore perfectly confounded with the experimental
group**: any instrument drift across the batch appears as a group difference, and no
statistical test can separate the two, because the design carries no information with which
to do so.

This is a real property of a real published dataset, it is not mentioned in the paper, and
the course treats it explicitly:

- Day 1 derives it from the file names in the proteomics preprocessing notebook.
- Day 3 uses it to interpret a suspiciously good classifier, and runs a partial control —
  removing proteins whose within-group variation tracks injection order.

The control is only partial, because the metabolomics injection order was never deposited
and most of that classifier's performance comes from the metabolites. The honest conclusion
is that batch cannot be excluded, and the way out is another cohort acquired in randomised
order — which is what the authors' independent PRM validation provides for their key
proteins.

The design lesson costs nothing at the bench: **randomise, or at least interleave, the
injection order**, and **record it**.
